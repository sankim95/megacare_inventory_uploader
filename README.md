# 약국 거래명세서 입고 반영 도우미

거래명세서 사진에서 품목을 구조화 추출하고 기존 상품리스트와 매칭한 뒤, 사용자가 승인한 행만 새 Excel 파일에 반영하는 단일 사용자용 로컬 웹앱입니다. 원본 Excel은 수정하지 않습니다.

## 개발·운영 문서

새 작업은 [`docs/00_PROJECT_CONTEXT.md`](docs/00_PROJECT_CONTEXT.md)에서 시작합니다. 이 문서가 역할별 권위와 읽기 순서를 정의합니다.

- 제품 목적·요구사항: [`PRD.md`](PRD.md)
- 현재 구현 아키텍처: [`docs/02_ARCHITECTURE.md`](docs/02_ARCHITECTURE.md)
- 확정·보류 결정: [`docs/03_DECISIONS.md`](docs/03_DECISIONS.md)
- 수용 기준과 검증 증거: [`docs/04_ACCEPTANCE_CRITERIA.md`](docs/04_ACCEPTANCE_CRITERIA.md)
- 현재 상태: [`docs/05_CURRENT_STATUS.md`](docs/05_CURRENT_STATUS.md)

[`handoff.md`](handoff.md)는 최초 요구와 2026-08-08 수정 전 리뷰를 보존한 역사적 문서이며, 현재 상태의 권위가 아닙니다.

## 요구 환경

- Python 3.12
- Node.js 20 이상
- macOS 또는 Linux
- OpenAI API를 이용한 실제 추출 시 `OPENAI_API_KEY`

## 설치

```bash
cp .env.example .env
PYTHON_BIN=/path/to/python3.12 ./scripts/setup.sh
```

`python3.12`가 PATH에 있으면 두 번째 명령은 `./scripts/setup.sh`로 줄일 수 있습니다. 설치 스크립트는 루트의 `.venv`와 `frontend/node_modules`를 준비합니다.

## OpenAI 설정

루트의 `.env`에서 다음 두 항목을 설정합니다.

```dotenv
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-5.6
```

- API 키는 `.env` 또는 셸 환경변수로만 읽으며 DB, 로그, 결과 Excel에 저장하지 않습니다.
- `.env`는 버전 관리에서 제외됩니다. 키가 들어간 파일을 공유하지 마세요.
- `OPENAI_API_KEY`가 없으면 앱과 테스트는 실행되지만 실제 사진 추출 요청은 실패로 기록됩니다. 키를 설정한 뒤 실패한 문서의 `이 문서 재시도`를 누르면 됩니다.
- AI에는 현재 처리 중인 사진 한 장만 전송하며 상품리스트 Excel 전체는 전송하지 않습니다.

## 기본 사용 흐름

1. `새 작업`에서 `Sheet` 시트와 필수 헤더가 있는 `.xlsx` 상품리스트와 PNG/JPG/JPEG/WEBP 거래명세서 사진을 선택합니다.
2. `임시저장`을 눌러 작업과 선택 파일을 저장합니다. 버튼을 누르기 전에는 작업 목록에 등록되지 않습니다.
3. 저장된 사진의 AI 추출을 시작합니다.
4. 사진 공급자, 거래일, 명세서 번호와 합계를 확인하고 OCR 오류를 수정합니다.
5. 모든 행의 매칭, `+재고`, 단가, 반영 체크와 상태를 검수합니다. 한 번 수동 확정한 OCR 매칭은 다음 작업의 같은 상품에 자동 적용됩니다.
6. 미매칭 신규 상품은 `사용자 직접 등록`으로 입력하고, 그 밖의 보류·미매칭·단가 충돌을 해소합니다. 확정 중복 사진은 업로드 화면에서 삭제합니다.
7. 승인자 이름을 입력하고 새 Excel을 생성한 뒤 결과를 내려받습니다.

완료 작업은 읽기 전용입니다. 결과 파일을 다시 내려받을 수 있고, `이 작업 복제`는 원본 상품리스트만 독립된 새 작업으로 복사합니다. 문서·품목·승인·결과 이력은 복사하지 않습니다.

## 데이터와 백업

`DATA_DIR`의 기본값은 루트의 `data/`입니다.

```text
data/
├── app.db       # 작업, OCR, 수정, 매칭, 승인 이력
├── uploads/     # 원본 Excel과 원본 사진
├── corrected/   # 로컬 보정 사진
└── exports/     # 생성된 결과 Excel
```

일관된 백업을 위해 앱을 먼저 종료한 뒤 `data/` 디렉터리 전체를 함께 복사하세요.

```bash
cp -a data "data-backup-$(date +%Y%m%d-%H%M%S)"
```

복구할 때도 앱을 종료하고 현재 `data/`를 별도 보관한 다음, 백업 디렉터리 전체를 원래 `data/` 위치에 놓고 실행합니다. DB 파일만 단독 복구하면 업로드·결과 파일 경로와 맞지 않을 수 있습니다.

## 문제 해결

- `Python 3.12 실행 파일을 찾지 못했습니다`: `PYTHON_BIN`에 Python 3.12 실행 파일의 절대 경로를 지정합니다.
- 상품리스트 업로드 차단: 시트명이 `Sheet`인지, 필수 헤더가 정확한지, 상품코드가 중복되지 않았는지 확인합니다.
- 사진 추출 실패: `.env`의 API 키를 확인하고 해당 문서만 재시도합니다. 다른 문서와 저장된 검수 내용은 유지됩니다.
- 내보내기 차단: 검수 화면에 표시된 보류·미매칭·중복·재고·단가 충돌 항목과 다음 행동을 모두 해소합니다.
- 비정상 종료 후 `추출 중` 또는 `내보내기 중`: 앱을 다시 실행하면 중단된 상태를 안전하게 검수 가능 상태로 복구하고 미확정 결과 파일을 정리합니다.

원본 Excel은 직접 수정하지 않습니다. 결과는 `data/exports/`의 새 파일로 생성되고, 성공적으로 재검증된 뒤에만 작업이 완료 처리됩니다.
